# 成品检查与选图

查看每张实际输出文件；编辑时同时查看原图，风格时同时查看对应参考。给每项写“通过 / 有偏差 / 未达成 / 未验证”及可见依据，不用总分掩盖主体错误。

## 判定顺序

1. **任务可用性（关键）**：是否还是用户要的主题？用途所需信息是否可读？主体身份、对象数量、重要形状、要求的字样和构图是否满足？多一个人、少一个物件不能用“整体好看”抵消。
2. **内容与构图（关键）**：转换有没有移动物件、改变人脸、地平线、裁切或反射？新图是否意外照搬参考？画幅按用户请求，不按风景模板。
3. **视觉目标（关键）**：分别核对目标色彩关系、明暗、表面尺度、软硬边缘、气氛；失败项须具体，如“冷蓝水面变棕黄”“细平纹变粗麻布”。没有加鸟不算失败，除非鸟属于需求。
4. **成品完整性**：无畸形/无意新增物件、文字/水印情况已记录；画幅、文件存在、可打开、最终文件位置已确认。不得凭查看工具成功就假定所有细节正确。

关键项未达成就不能标为成品通过。无法验证的人物身份、文字或像素等价明确列为未验证。图像看起来顺眼不替代逐项检查；其他 agent 的历史 PASS 也不替代本次验收。

## 修正与停止

按影响用途最大的一个或两个偏差修正，保留已经正确的属性；每版重新看图。不改风格去掩盖内容问题，不以换场景解决局部失败。默认最多两次修正，用户预算优先。

有一版关键项通过则从通过版本中选最合适的；最后一版退步时保留之前更好的版本。若达到上限仍失败，保存最佳结果，状态为部分达成/未达成，写清未达标项和下一步所需条件。工具不可用或文件未取得，则是未执行/未完成，不是“应该可以”。

## 每张交付记录

- 请求与用途；主题；输入角色和为什么选这组参考。
- 必须保留、可以改变、画幅与关键验收项。
- 实际工具与完整提示词；每版图片路径与查看记录。
- 逐项观察；需要修正的具体偏差、每轮改了什么。
- 最终选图路径、选择依据、通过/部分达成/未达成/未验证状态与残留问题。

文字记录不能代替最终图片。交付最终文件及必要的原图对照，让用户直接查看；准确说清哪些要求已满足、哪些仍未证明。公开参考须有发布依据，用户照片默认本地保存。
